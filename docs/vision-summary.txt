AGENTIC STRUCTURED CASHFLOW PLATFORM - VISION SUMMARY
=====================================================

NOTE FOR THE DECK GENERATOR
---------------------------
Build a 3 to 4 slide deck from the outline below. The audience is senior and
non-technical. Keep it light on detail and heavy on vision, with one idea per
slide and few words. The deck is about the vision only. Do not describe current
build status, features already built, timelines or resourcing.
Suggested visual on slide 2: a simple three-box flow,
  User (plain English)  ->  AI Agent  ->  Cashflow Engine (validated)
with results flowing back to the user.


SLIDE 1 - THE IDEA: ASK A QUESTION, GET A MODEL RUN
---------------------------------------------------
Headline: Run structured-credit cashflows by talking to them.

- An AI assistant that anyone at the firm can chat with in plain English to
  set up deals, change assumptions and run cashflow scenarios.
- Behind it sits a fixed, validated cashflow engine. The engine does all the
  math. The AI only drives it.
- Example asks:
    "Run this deal at 15 CPR, 2 CDR and 30% severity. Which tranches take
     write-downs?"
    "Show me how the M-2 tranche's WAL changes if prepayments slow by half."
    "Compare this tranche against every similar deal issued this year."
- The goal is to open structured cashflow modeling to everyone at the firm,
  not just a few specialists.


SLIDE 2 - HOW IT WORKS: AI AS THE INTERFACE, ENGINE AS THE SOURCE OF TRUTH
--------------------------------------------------------------------------
Headline: The AI never makes up a number.

- User: asks in plain English (analyst, risk reporter or executive).
- AI agent: works out the request, picks the deal and the assumptions
  (CPR, CDR/CER, severity, rates), runs the engine and explains the results.
- Cashflow engine: a static, predetermined model of each deal's waterfall,
  built from the offering documents and tied out to Intex, the cashflow
  engine the firm uses today. The same inputs always give the same outputs.
- Every answer traces back to a logged run that can be reproduced, so each
  number is auditable.
- What users get back:
    - plain-English answers with charts in the chat
    - Excel workbooks of the full cashflows
    - drafted reports and memos (run summaries, risk write-ups)
    - a complete audit trail of every run


SLIDE 3 - THE PAYOFF: ACCESS AND COMPARABLES
-------------------------------------------
Headline: Everyone can model, across the whole market.

Access
- Junior analysts, risk reporters and senior leaders can all run and question
  models directly, without waiting on a specialist or a vendor-tool seat.
- Questions that take hours of manual setup today become a short conversation.

Comparables
- One consistent engine across a universe of deals means apples-to-apples
  comparisons: the same assumptions and methodology applied to every deal.
- Pull a universe or a peer set on demand for relative value, pricing context
  and portfolio review.
- "How does this deal's subordination and loss coverage compare with every
  CRT deal from the last two years?"


SLIDE 4 - WHERE IT GOES: ONE INTERFACE, THE WHOLE MORTGAGE CREDIT UNIVERSE
--------------------------------------------------------------------------
Headline: Start with CRT. Extend to all of mortgage credit.

- GSE credit risk transfer:
    - Freddie Mac STACR
    - Fannie Mae CAS
    - Freddie Mac ACIS and Fannie Mae CIRT (insurance-based CRT)
- Non-QM securitizations
- Private-label RMBS
- The same chat interface works for every deal type. Each new asset class
  adds a validated engine behind it, tied out to Intex.
- The end state is a single place to model, compare and report on the
  mortgage credit universe.
