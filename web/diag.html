What the engine page actually loads: the data bundle data/bundle.js (a script, loaded with importScripts: the manifest, every project file and the three wheels, verified by SHA-256 after decoding) and the Python runtime from the first runtime candidate whose pyodide-lock.json answers: this site's pyodide/, then the jsdelivr release CDN. The first row loads the bundle the same way (a script tag) and says whether it parsed; the next rows fetch each candidate's lock file. If the bundle row passes and one runtime candidate passes, the engine page can start.

The remaining rows fetch, one at a time, every file the site serves (the manifest is fetched with a cache-busting query and every file it lists is then added; when the manifest itself cannot be fetched, the copy inside the bundle is used to list them). "Test" fetches one URL and reports the HTTP status, byte count, the SHA-256 against the manifest, the content type and the time taken. A thrown error is shown with the browser's own name and message. Project files and wheels are served under neutral names, files/<hash>.bin (the "What" column gives the real name); the runtime under pyodide/ keeps Pyodide's own names (pyodide.asm.wasm, python_stdlib.zip, pyodide-lock.json, two .whl). A proxy that filters by file type shows up as: script rows pass, .json, .bin, .whl or .wasm rows fail with TypeError: Failed to fetch.
