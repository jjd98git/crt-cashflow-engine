Engine load diagnostics

Tests, one file at a time, every URL the cashflow engine page fetches while it starts, and says exactly which request fails and how. Nothing here runs the engine.

Files

Every URL below is on this site; the page contacts no other origin. The manifest is fetched first (with a cache-busting query) and every file it lists is then added. "Test" fetches one URL and reports the HTTP status, byte count, the SHA-256 against the manifest, the content type and the time taken. A thrown error is shown with the browser's own name and message.

File names: project files and wheels are served under neutral names, files/<hash>.bin, so no .yaml, .csv, .json or .whl appears in those URLs; the "What" column gives the real name. The Python runtime under pyodide/ is the exception: Pyodide fetches its own files by name, so that directory keeps pyodide.asm.wasm, python_stdlib.zip, pyodide-lock.json and two .whl files. If only the pyodide/ rows fail, something between this browser and the site is filtering by file extension or content type (a .wasm block looks exactly like that).
